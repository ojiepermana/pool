# Feature inventory and parity matrix

**Date:** 2026-11-14. Pgpool-II baseline: 4.7.3. Every POOL capability is Research or Planned. None is Implemented or Tested. This is a documented planning corpus, not 100 percent parity.

The baseline column distinguishes reference behavior from POOL additions. Group references identify the controlling manual section. Protocol rows use the PostgreSQL contract because proxy compatibility requires executable evidence. The separate [configuration inventory](research/pgpool-configuration-inventory.md) accounts for each option spelling in the pinned streaming sample.

P0 covers the core and initial operating scenario. P1 extends operations and HA. P2 covers advanced or research scope. The [milestones](plan/milestones.md) define the release gates. The milestone is when the full row is assessed. Earlier slices must satisfy the subset they expose: for example, the first write in scope 004 already requires verified writer authority (F-056/F-065). A refusal, disabled feature or documented disposition qualifies only that behavior. For example, V1 must refuse automatic promotion (F-075), while a working cache invalidation API (F-134) requires a separate cache decision. Research rows have no release commitment.

## Coverage limits

The inventory covers the documented subsystem families, 15 PCP operations, 12 SQL command pages, 7 SQL wrappers, the daemon and 6 utilities, plus the linked 207-spelling sample and 186-name runtime parameter census. It does not claim an audit of every C path, every undocumented alias, optional build flag, all mode specific samples or every release note regression. Before a full parity claim, pin the source archive and binary hashes, reconcile all manual entries and samples, build differential tests, and mark each applicable row Tested with evidence. Excluded features remain visible rather than being removed from the denominator.

## Initial exclusions

Transaction and statement multiplexing, general session migration, automatic promotion, native and snapshot middleware replication, logical replication routing, result caching, PCP wire compatibility, pgpool_adm compatibility and a dashboard are excluded from V1. Their rows preserve the future decision rather than claiming implementation.
